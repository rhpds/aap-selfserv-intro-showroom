[#content-discovery-overview]
== What is content discovery?

Ansible content rarely lives in one place:

* **Private Automation Hub** holds Red Hat **certified** and **validated** collections
* **GitHub / GitLab** holds playbooks, roles, custom collections, and CI configuration
* **Individual teams** often know about “their” repos, but others cannot find them

**Content discovery** continuously syncs that content into a single, searchable catalog so users can see what is available to them. Administrators choose what is discoverable and how sync runs (on a schedule or on demand). Governance stays with the AAP / platform team; discovery is the user-facing catalog.

Automation Portal’s content discovery brings those sources into one view so teams can browse what the platform already provides.

Sidebar items such as **Git Repositories**, **Collections**, and **Execution Environments** only appear for users whose portal role includes those permissions.
In this module you will grant that access to `portal-users`. Leave `portal-rhel-team` unchanged so you can see how RBAC controls who gets content discovery.

== Discover Git repositories

The **Git Repositories** section of the portal shows Git repos that have been made discoverable for your organization. Teams can open source links, see related automation content, and understand what already exists in Git.

=== Browse repositories

* Open the portal navigation and select **Git Repositories**.

* If the catalog shows **No Git repositories found**, click **Sync Now** (top right) and wait for the sync to finish, then refresh the page.
  Discovery only lists org repositories that look like Ansible collections (they contain a `galaxy.yml`).

* Review the list of repositories available in this lab environment.

[#collections]
== Discover collections

Collections package Ansible content (roles, modules, plugins) for reuse.
In the portal, **Collections** discovery lets users browse what Hub and related sources have made available, including Red Hat content and collections your organization publishes.

=== Open the Collections view

* In the portal, open **Collections**.

* If the list is empty, click **Sync Now** so the portal pulls collections from this instance’s Private Automation Hub.
  The first sync can take several minutes while Hub and the portal finish indexing content. Wait for it to complete, then refresh if the list still looks empty.

* Notice that you can browse collections without leaving the portal or logging into Hub separately for a first look.

image::m04-collections.png[PLACEHOLDER: Automation Portal Collections catalog. Left navigation highlights Collections. Main area lists collections synced from Private Automation Hub, with Sync Now available if the list is empty. Replace this placeholder with a real screenshot before publish.,link=self,window=blank]

=== Use filters, search, and stars

The **Filters** panel on the left includes search, **Personal** (including **Starred**), **My Org**, **Source Type**, **Tags**, and **Show latest version only**.

image::m04-collections-filter.png[Automation Portal Collections Filters panel with search, Personal Starred, My Org, Source Type, Tags, and Show latest version only.,link=self,window=blank]

* Try **Source Type**, **Tags**, and the search box to narrow the list.
  Notice that the catalog can include several kinds of content:

** **Certified** collections: Built and supported by Red Hat and partners (for example `amazon.aws`, `cisco.ios`)
** **Validated** collections: Expert-led roles and playbooks for common operational tasks that you can customize for your environment
** **Community** collections: Built and maintained by the community (for example `community.general`)
** **Custom / published** collections: Content your organization publishes (in this lab, the `parasol` namespace)

* Open a collection you expect to reuse later, **star** it, then return to **Collections** and select **Starred** under **Personal**.
  Confirm the starred collection appears in that filtered list.

✅ **Expected result**: You can browse certified, validated, and community Hub content, find at least one `parasol.*` collection (for example `parasol.network`, `parasol.platform`, or `parasol.cloud`), and filter the catalog down to collections you have starred.

[IMPORTANT]
====
If `parasol` collections do not appear, Hub sync or publish for this instance may still be running.
Wait a minute, refresh the Collections view, or ask your facilitator. Do not skip ahead to Module 5 until you can see custom collections. Module 5 builds on that content.
====

[NOTE]
====
**Key learning**: Content discovery does not replace Hub or Git.
It gives SMEs and platform admins a **unified place to see** what automation assets exist so they can choose the right collections and repositories when they build or run automation later.
====

== Learning outcomes

By completing this module, you should now understand:

* **How portal RBAC controls content discovery** - Sidebar items appear only for roles that include the matching view permissions
* **What content discovery is** - A unified portal catalog over Hub and Git so teams can find automation available to them
* **How repositories appear in the portal** - Git repos are listed for discovery and navigation, separate from EE Builder
* **How collections appear in the portal** - Users can browse and filter Hub-backed content, including certified, validated, community, and custom collections
